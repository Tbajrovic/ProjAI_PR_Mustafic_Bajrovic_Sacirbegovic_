# PatternScope AI

Hybrid pattern recognition (digits, shapes, symbols) using KNN, Naive Bayes, MiniMLP, A* Matcher and a rule-based fallback.

## Mandatory Project Setup (Does not work without these steps)

Data: Download the datasets from `https://drive.google.com/drive/folders/1hYimit3pEeRCuQSTrUa6oRGxfFsd3jKz?usp=sharing` and put datasets in the resources folder as **`resources/mnist/`**, **`resources/datasets/`** and **`resources/testing_samples/`**. Paths are exe-relative.

## Build and run (macOS/Linux)

```bash
cd Implementation &&
mkdir -p build && cd build
cmake .. && make

# 1. Pre-train models (required, takes a few minutes)
./trainer

# 2. Start the app (run from build/ so models are found)
cd build
./PatternVision.app/Contents/MacOS/PatternVision

# Optional: terminal predictor (prompts for image path)
./predictor digits   # or shapes, symbols

# Optional: batch accuracy on test data
./patternScopeAI_cli           # digits
./patternScopeAI_cli shapes    # or symbols
```

If you open the app from elsewhere (e.g. double-click or `open PatternVision.app`) and not as explained above, set `PATTERNSCOPE_RESOURCE_ROOT` to the project **resources** directory first, or the GUI will not find the models that are exported in the resources.

## Build and run (Windows)

Prerequisites: install CMake ([cmake.org](https://cmake.org)) and a C++ compiler — easiest is Visual Studio 2022 Community with the "Desktop development with C++" workload.

Data: same mandatory step as above — download the datasets and place them in `resources/mnist/`, `resources/datasets/`, and `resources/testing_samples/`.

Run this from inside the project's `Implementation` folder (the outer folder name may vary depending on how you obtained the project — e.g. cloned repo vs. a zipped submission):

```cmd
cd Implementation
mkdir build
cd build
cmake ..
cmake --build .
```

`cmake --build .` replaces `make`, which isn't available on Windows by default — it automatically invokes whichever compiler CMake configured (MSVC or MinGW).

If CMake picked the Visual Studio generator (the default when Visual Studio is installed), the built `.exe` files land in a `Debug\` subfolder rather than directly in `build\` — check with `dir /s *.exe` if you don't see them where expected.

```cmd
:: 1. Pre-train models (required, takes a few minutes)
trainer.exe

:: 2. Start the app (run from the same folder as trainer.exe, so models are found)
PatternVision.exe

:: Optional: terminal predictor (prompts for image path)
predictor.exe digits   :: or shapes, symbols

:: Optional: batch accuracy on test data
patternScopeAI_cli.exe           :: digits
patternScopeAI_cli.exe shapes    :: or symbols
```

Unlike the Mac `.app` bundle, these are plain `.exe` files on Windows — same rule applies: run them from the folder they were built into so resource paths resolve correctly.

### Known natID SDK issues on Windows (v4.1.0)

If `PatternVision.exe` builds successfully but crashes or won't launch, check these first — all three are natID SDK packaging inconsistencies, not bugs in this project's code:

- **"Entry Point Not Found" on launch** (e.g. `gui::Consumer::onToolbarsPopoverSelectionChange`) — your local `natGUI.dll` may be a newer SDK version than your paired headers/import libs (`Work\Common\Include`, `other_bin\myLib\natGUI.lib` / `natGUID.lib`). Re-copy the current headers and `.lib` files from your `natID.SDK` install to overwrite the old ones, then do a full clean rebuild (delete `build\`, reconfigure, rebuild).
- **Crashes immediately on startup** (`_debugbreak()` / `abort()` inside `gui::Application`'s constructor) — Visual Studio's auto-generated `-devResPath=...` debug argument isn't quoted. If your Windows username contains a space, Windows splits it into multiple arguments and the app can't parse it. Fix: in Project Properties → Debugging → Command Arguments, wrap the value in quotes. Note this field is regenerated by `cmake ..`, so you may need to re-quote it after reconfiguring.
- **"Cannot open xml file... natGUI.xml" then `abort()`** — natID looks for `natID.SDK\Work\Common\ResConfigs\natGUI.xml`, but the SDK only actually ships files at `natID.SDK\Common\ResConfigs\` (no `Work\` folder in between). Workaround: create `natID.SDK\Work\Common\ResConfigs\` and copy the contents of `natID.SDK\Common\ResConfigs\` into it.

## GUI (PatternVision++)

Mode selection, load image from file, live prediction, per-model comparison, Yes/No feedback. Run from `build/` as above so resource paths match.

**Confusion matrices:** Click **Metrics** to show saved confusion matrices and accuracy per model (KNN, N. Bayes, MLP, A*). Data comes from the last trainer run (stats files in each mode folder). **Accuracy** is the fraction of test samples predicted correctly. The **confusion matrix** has one row per true class and one column per predicted class; cell (i,j) is how often true class i was predicted as j. The diagonal (i,i) is correct predictions for class i; off-diagonal cells are confusions.

## Backend

- **Engine::predict(mode, image)** — ensemble plus fallback; returns `PredictionResult` (finalLabel, finalConfidence, modelComparison).
- **Engine::updateModel(mode, image, correctLabel)** — incremental learning (Yes feedback).
- **Engine::getMetrics(mode, modelName)** — loads saved confusion matrix (e.g. from trainer's `*_stats.txt`).

Models and stats under `ResourcePath::getModelsDir()` → `resources/models/{digits|shapes|symbols}/`.
